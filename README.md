Contributing
Contributions, suggestions, documentation fixes, and carefully scoped improvements are welcome where repository settings permit them.
Review the README, open issues, and existing contribution guidance.
Fork the repository if you do not have direct write access.
Create a focused branch:
git checkout -b docs/describe-your-change
Make a coherent change and review it:
git diff --check
git diff
Commit the intended file(s):
git add README.md
git commit -m "docs: improve project documentation"
Push the branch and open a Pull Request:
git push -u origin docs/describe-your-change
Explain what changed, why it matters, and how it was checked.
Do not commit unrelated local changes, credentials, private data, or files that are not intended for publication.
Security and Responsible Use
Never commit passwords, API keys, personal access tokens, private keys, session cookies, or production secrets.
Use environment variables or an appropriate secret manager for sensitive configuration.
Review the target branch and staged file list before committing.
Test changes in a non-production environment when practical.
Confirm the deployment target before merging or publishing changes.
Keep third-party dependencies and deployment instructions up to date.
Use tools and infrastructure only on systems you own or are explicitly authorized to test.
Report suspected vulnerabilities privately to the maintainer rather than publishing exploit details in an issue.
